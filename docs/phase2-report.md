## Обнаруженные проблемы и исправления

| Приоритет | Проблема | Реализованное исправление |
|---|---|---|
| P1 | Bluetooth worker мог потерять сигнал завершения перед wait; жизненный цикл Initialize/Finalize не был отдельно сериализован | Предикат condition_variable, отдельный lifecycle mutex, один общий worker, join последнего пользователя |
| P1 | COM и DeviceWatcher не имели полного симметричного завершения | COM принадлежит worker; события отписываются, Stop дожидается завершения callbacks; кэш WinRT освобождается до CoUninitialize |
| P1 | Ошибка запуска/остановка watcher не восстанавливались | Повтор запуска при Stopped/Aborted, перевод сохранённых устройств offline, проверка состояния максимум через 15 секунд |
| P1 | Offline Classic endpoint мог передать старый заряд активному BLE endpoint | Чистая функция объединения по container ID выбирает заряд только подключённых endpoints; 0% остаётся валидным значением |
| P1 | Старые ответы/команды яркости и перезапуск fallback могли восстанавливать устаревшие значения | Sequence IDs, отклонение старых команд, сохранение монотонного номера по request/status, тесты быстрых последовательностей |
| P1 | При потере чтения яркости прежнее значение сохранялось как будто актуальное | После периода settling недоступность публикуется как -1; при восстановлении чтения синхронизация возобновляется |
| P1 | DDC перебирал мониторы при каждой записи и мог перейти к другому после ошибки | Запись остаётся на выбранном HMONITOR; повторный выбор разрешён при чтении после смены топологии; физические handles освобождаются RAII |
| P1 | Weather принимал синтаксически повреждённый JSON, если нужные фрагменты удавалось найти regex | Ограниченный по размеру/глубине JSON decoder, проверка типов и временных диапазонов, null сохраняет место в массиве и не становится 0°C |
| P1 | 45-секундный Lua watchdog погоды мог инициировать запрос до завершения WebParser | Повтор только после error callback с прежним backoff; обычный UpdateRate=900 не изменён |
| P1 | Auto Low Power сохранял буквальное `(1-PowerState)`, вызывавшее ошибки формул Clock | Producer записывает вычисленное `(1-[PowerState])`; начальное состояние сохраняется при Refresh; текущее значение исправлено на 0 без изменения остальных настроек |
| P2 | SetupAPI handle освобождался вручную, чтение uint32 могло быть невыровненным | RAII для HDEVINFO, memcpy для чисел, DIGCF_PRESENT для актуальных данных |
| P2 | Bluetooth пересобирал snapshot в callback под mutex и повторно копировал строку | События объединяются за 100 ms; snapshots публикует worker; строка копируется в measure только при смене generation |
| P2 | Любое событие могло провоцировать SetupAPI | Отдельные флаги публикации и запроса метаданных; scan при подключении и через 15 секунд при наличии активных устройств |
| P2 | Изменение имени/категории не обновляло adaptive cell | В signature включены имя и категория, перерисовка объединена для всех изменённых cells |
| P2 | Нормализация GUID могла нарушить старые Pinned ID с другим регистром | GUID сопоставляется без учёта регистра и в виджете, и в настройках; сохранённый PinnedId не переписывается |

## Ограничения и риски

- Не выполнялись физические отключения Bluetooth, sleep/hibernation, смена DPI,
  разрешения, темы Windows, топологии дисплеев, реальная проверка всех 60/120/144 Hz,
  быстрые переключения реальных треков и аппаратный scroll/drag. Логика покрыта
  моделями, но это не заменяет аппаратную приёмку и визуальную сверку.
- Работа без перезапуска несколько часов/суток не проверена. Краткие lifecycle
  и process-прогоны не доказывают отсутствие любых долгосрочных утечек.
- Объединение Bluetooth опирается на ContainerId Windows. Для endpoints без него
  сохраняется прежний fallback на endpoint ID; гарантировать физическую
  дедупликацию таких устройств без надёжной идентичности нельзя.
- Восстановление watcher при Stopped/Aborted реализовано, но поведение конкретного
  драйвера после sleep/radio toggle пока не подтверждено аппаратным тестом.
- SetupAPI опрашивает заряд раз в 15 s у подключённых устройств, поскольку не все
  драйверы отправляют battery events. Публикация событий отделена от этих scan.
- Обложки сравниваются по содержимому раз в секунду: провайдер может перезаписать
  тот же путь. Размер ограничен, повторное декодирование и cache write исключены,
  но само чтение для обнаружения изменения сохранено.
- Базовые UI ticks Music/Slider сохранены для совместимости hover/drag. Static
  meters не обновляются постоянно; фактическая частота renderer frames не измерена.
- WMI/DDC аппаратные вызовы не имеют общего безопасного механизма отмены здесь.
  Finalize корректно ждёт worker, поэтому плохой драйвер может увеличить выгрузку.
- DDC сохраняет прежнюю политику выбора монитора; новый пользовательский selector
  не добавлялся. Реальная работа нескольких физических дисплеев требует проверки.
- PowerShell fallback сохранён, исправлен и синтаксически проверен, но полный
  аппаратный прогон fallback отдельно от native backend не выполнялся.
- WebParser сохраняет штатные сетевые timeout/error callbacks. Без их завершения
  Lua не запускает параллельный retry; отдельного принудительного отменяющего
  сетевой поток watchdog не добавлено.
- Источник яркости восстановлен из существующего ScrollFix developer bundle.
  Совместимость протокола и тесты проверены; принадлежность исходного установленного
  бинарника ровно этому source revision по одному hash установить нельзя.
- Внешний вид, размеры и графические assets не переделывались. Визуальная GUI
  приёмка не выполнялась по ограничению задачи. Phase 3 не затрагивалась.

## Исправление после сообщения пользователя — 19 ноября 2026

При проверке реального Bluetooth snapshot выяснилось, что Windows оставлял у
отключённых iPad и iPhone `IsConnected=true`. Плагин теперь дополнительно
запрашивает `System.Devices.Aep.IsPresent` и считает endpoint отключённым,
если он больше не присутствует. Это соответствует [описанию свойства Microsoft](https://learn.microsoft.com/en-us/windows/apps/develop/devices-sensors/device-information-properties): paired endpoints остаются в кэше даже после исчезновения устройства. До исправления оба устройства публиковались как `connected=1`; после установки оба публикуются как `connected=0`. Fallback Monitor зависит от этого флага. Параметры Auto/None/Pinned не менялись.

В backend яркости старое чтение драйвера могло по истечении пяти секунд
заменить последнюю цель слайдера. Теперь такое чтение не публикуется как
подтверждённое значение. Добавлен тест: быстрые команды от 100 до 60,

## Дополнительное исправление яркости — 19 ноября 2026

Диагностический журнал предыдущей версии показывает конкретный сбой: после
последней команды `id=56 target=100` плагин опубликовал `56 5` и Lua выполнил
`SYNC incoming=5 responseId=56`. При этом `confirmed=5`, то есть DLL
возвратила старое подтверждённое значение после неудачного аппаратного Set.
Позже пришло `incoming=100` с тем же ID. Это воспроизводит скачок к прежнему
уровню и обратно. Предыдущая правка касалась устаревших ответов чтения после
успешной записи и не закрывала этот путь отказа Set.

Теперь ошибка Set не публикует прежний `confirmed` уровень. Пока актуальное
значение нельзя подтвердить, DLL возвращает `-1`; Lua показывает `--`,
сохраняет последнюю цель анимации и принимает дальнейшие шаги колеса.
Только чтение, совпадающее с последней целью, завершает её подтверждение.
Добавлены тесты отказа Set и продолжения прокрутки во время временной ошибки.
**3/3 CTest и 24/24 Lua-теста проходят**. Установлены новая x64 DLL и Lua,
Rainmeter перезапущен. Физическое быстрое колесо в этом сеансе не воспроизводилось;
проверены лог прежнего сбоя и моделируемая последовательность отказов драйвера.


## Отображение процента во время записи

После обработки временной ошибки backend возвращал `-1`, а Lua показывал `--`

команды слайдер удерживает выбранный процент. `--` остаётся только для состояния,
когда исходное системное значение ещё не известно и пользователь не задавал цель.

## Исправление краткого `--` после подтверждения

Причина: после уже полученного корректного значения очередное `-1` из DLL
сбрасывало флаг `ready`, поэтому проценты на мгновение заменялись двумя
полосками. Теперь `-1` не меняет последнее достоверное или выбранное значение.
До первого успешного чтения начальный `--` сохраняется. На реальном backend
текущее чтение проверено: `0 100` стабильно в шести read-only отсчётах.
Lua-регрессия воспроизводит переход `60 → -1 → 58`; тесты 25/25 проходят.
Установленный Lua обновлён и skin Brightness обновлён через Rainmeter.
